# Plan d'implémentation — 01 Socle Tauri 2

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE — utiliser superpowers:subagent-driven-development
> (recommandé) ou superpowers:executing-plans pour dérouler ce plan tâche par tâche.
> Les étapes utilisent des cases à cocher (`- [ ]`) pour le suivi.

**Objectif :** une chaîne de build qui produit un `.app` macOS lançable, avec une CI verte.

**Architecture :** frontend React/TypeScript servi par Vite, coquille native Tauri 2 en
Rust. Le scaffold est **écrit à la main** plutôt que généré par `create-tauri-app` : le
dépôt n'est pas vide (`AGENTS.md`, `specs/`, `plans/`, `.git`) et un générateur y ferait
des dégâts ou exigerait une danse de déplacement de fichiers. Les fichiers concernés sont
courts et intégralement donnés ici.

**Stack :** pnpm · Tauri 2 · React · TypeScript strict · Vite · Biome · Vitest · Playwright

**Spec :** `specs/01-socle-tauri.md`

---

## Note sur la méthode

Une chaîne de build ne se teste pas en TDD : il n'y a pas d'unité de comportement à
spécifier avant de l'écrire. Les tâches 1, 2, 4, 5, 6 et 7 sont donc vérifiées par
**exécution de commande et observation de la sortie attendue** — c'est l'équivalent
honnête de la boucle rouge/vert ici. La TDD réelle commence en tâche 3, et gouverne
entièrement les plans `02` et `07`.

- [ ] **Étape 3 : écrire les quatre fichiers TypeScript**

**Deux programmes, pas un.** `@types/node` déclare `setTimeout` globalement et **écrase la
déclaration DOM** : avec `"node"` dans un `types` unique, `useRef<number | null>(null)`
pour un timer de debounce ne typechecke plus (`Type 'Timeout' is not assignable to type
'number'`), et `process.env` compile silencieusement depuis du code navigateur où il est
indéfini à l'exécution. D'où la séparation — c'est aussi la raison pour laquelle
`create-vite` la fait.

`tsconfig.json` est réduit à un fichier de solution avec des références. C'est ce qui
garantit qu'un éditeur ouvrant un fichier de `src/` résout le programme applicatif : un
simple fichier de base sans `include` serait pris par défaut et inclurait tout,
ramenant les types Node dans `src/`.

`tsconfig.base.json` — options partagées :

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "moduleDetection": "force",
    "noEmit": true,
    "skipLibCheck": true,
    "resolveJsonModule": true
  }
}
```

`tsconfig.app.json` — le programme applicatif, **sans `node`** :

```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "composite": true,
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.app.tsbuildinfo",
    "lib": ["ES2022", "DOM", "DOM.Iterable"],
    "jsx": "react-jsx",
    "types": ["vitest/globals", "vite/client"]
  },
  "include": ["src"]
}
```

`tsconfig.node.json` — le programme outillage. `e2e` y est listé par anticipation de la
tâche 6 :

```json
{
  "extends": "./tsconfig.base.json",
  "compilerOptions": {
    "composite": true,
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.node.tsbuildinfo",
    "lib": ["ES2022"],
    "types": ["node"]
  },
  "include": ["scripts", "vite.config.ts", "playwright.config.ts", "e2e"]
}
```

`tsconfig.json` — la solution :

```json
{
  "files": [],
  "references": [{ "path": "./tsconfig.app.json" }, { "path": "./tsconfig.node.json" }]
}
```

`composite: true` cohabite sans problème avec `noEmit: true` en TypeScript 7 — vérifié,
`tsc -b` sort en 0. La restriction des anciennes versions n'existe plus. Les
`tsBuildInfoFile` sont placés sous `node_modules/`, donc déjà ignorés par git.

C'est aussi ce qui impose `tsc -b` plutôt que `tsc --noEmit` dans les scripts : `-b`
construit les deux références en une invocation. Un typecheck qui n'en couvrirait qu'une
serait pire qu'inutile — il donnerait une fausse assurance.

- [ ] **Étape 4 : écrire `vite.config.ts`**

La cible d'exécution est **WKWebView**, pas Chrome. Le plancher supporté est **macOS 13
Ventura, soit Safari 16.4** — quatre ans d'ancienneté, et `oklch()` comme
`color-mix(in oklab, …)` y sont couverts, ce dont le handoff a besoin.

`cssTarget` est déclaré explicitement **même s'il vaut la même chose que `target`**.
Sans lui il en hérite silencieusement, et la minification CSS de Vite 8 — qui passe par
lightningcss — réécrit `oklch()` en `lab()` : une conversion d'espace colorimétrique
faite au build, sans fallback, sur un projet dont l'exigence est que ce qui est écrit
soit ce qui est servi. C'est l'héritage implicite qui est le piège, pas la valeur.

`server.watch.ignored` est nécessaire parce que Vite 8 n'ignore par défaut que `.git`,
`node_modules`, `test-results` et son cacheDir, et que chokidar ne lit pas `.gitignore` :
sous `tauri dev`, chaque rebuild Rust écrit dans `src-tauri/target` et ferait churner le
watcher.

Attention enfin : `build.target` n'abaisse que la **syntaxe**, pas les API. `lib: ES2022`
autorise des méthodes que Vite ne polyfille pas — la cohérence avec le plancher macOS
reste à la charge du code.

```ts
import { defineConfig } from 'vitest/config'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  clearScreen: false,
  server: { port: 5173, strictPort: true, watch: { ignored: ['**/src-tauri/**'] } },
  build: { target: 'safari16.4', cssTarget: 'safari16.4' },
  test: {
    environment: 'jsdom',
    globals: true,
    setupFiles: ['./src/test/setup.ts'],
  },
})
```

- [ ] **Étape 2 : régler fenêtre, identité et CSP dans `src-tauri/tauri.conf.json`**

`titleBarStyle: "Overlay"` avec `hiddenTitle: true` donne la barre superposée : macOS
garde ses feux tricolores, on dessine l'intérieur. La CSP interdit toute origine
externe — c'est ce qui rend la contrainte « aucune requête réseau » structurelle et
non déclarative.

```json
{
  "productName": "DoraBase",
  "version": "../package.json",
  "identifier": "com.dorabase.desktop",
  "app": {
    "windows": [
      {
        "title": "DoraBase",
        "width": 1360,
        "height": 814,
        "minWidth": 960,
        "minHeight": 600,
        "resizable": true,
        "titleBarStyle": "Overlay",
        "hiddenTitle": true
      }
    ],
    "security": {
      "csp": "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; font-src 'self'"
    }
  },
  "bundle": {
    "active": true,
    "targets": ["app", "dmg"],
    "macOS": { "minimumSystemVersion": "13.0" }
  }
}
```

`minimumSystemVersion` doit être déclaré : le défaut de Tauri est `10.13`, soit un
WKWebView très antérieur à Safari 16.4. Sans cette ligne, la cible de build et le
plancher du bundle racontent deux histoires différentes, et l'app s'installerait sur des
systèmes où son CSS ne tient pas.

`style-src 'unsafe-inline'` est nécessaire parce que Vite injecte les styles en ligne
en développement. À resserrer si un jour on ne sert plus que du CSS compilé.

## Tâche 6 : Playwright, dormant

**Fichiers :** créer `playwright.config.ts`

Playwright est installé et configuré ici, mais **n'entre pas en CI** : il n'y a encore
aucun écran à photographier. Il prend son service au plan `07`.

- [ ] **Étape 1 : écrire la configuration**

```ts
import { defineConfig } from '@playwright/test'

export default defineConfig({
  testDir: './e2e',
  webServer: { command: 'pnpm dev', port: 5173, reuseExistingServer: true },
  use: { baseURL: 'http://localhost:5173', viewport: { width: 1360, height: 814 } },
  expect: { toHaveScreenshot: { maxDiffPixelRatio: 0 } },
})
```

`maxDiffPixelRatio: 0` est volontaire : sur un projet dont l'exigence est la fidélité
au pixel, une tolérance serait un renoncement silencieux.

- [ ] **Étape 2 : couvrir `e2e/` au typecheck**

Ajouter `"e2e"` à `include` dans `tsconfig.json`. Sans ça les tests Playwright ne sont
pas typecheckés — et le piège est subtil : comme Vitest tourne avec `globals: true`, un
fichier e2e qui oublierait d'importer `test` et `expect` depuis `@playwright/test`
compilerait quand même, en résolvant silencieusement vers les globals de Vitest.

- [ ] **Étape 3 : installer le navigateur**

```bash

```

## Tâche 7 : CI

**Fichiers :** créer `.github/workflows/ci.yml`

- [ ] **Étape 1 : écrire le workflow**

```yaml
name: CI
on: [push, pull_request]

jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy
      - uses: swatinem/rust-cache@v2
        with:
          workspaces: src-tauri
      - run: pnpm install --frozen-lockfile
      - run: pnpm typecheck
      - run: pnpm lint
      - run: pnpm test
      - run: cargo fmt --all --check
        working-directory: src-tauri
      - run: cargo clippy --all-targets -- -D warnings
        working-directory: src-tauri
      - run: pnpm tauri build
```

- [ ] **Étape 2 : reproduire la CI en local**

```bash
pnpm typecheck && pnpm lint && pnpm test \
  && (cd src-tauri && cargo fmt --all --check && cargo clippy --all-targets -- -D warnings) \
  && pnpm tauri build
```

Attendu : tout sort en 0.
